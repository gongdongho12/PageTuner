# Readable document file export v1

This contract exports the selected document/chapter as a human-readable TXT or
Markdown file. It does not reconstruct the original Markdown or EPUB, fetch or
combine additional documents/remote chapters, or provide an identity-preserving
backup. Use the separate portable
ZIP exchange for identities, revisions, notes, bookmarks, and related metadata.
Only the selected book title, chapter title, and ordered paragraph text enter
the generated text. Provider settings, credentials, notes, translation caches,
and other documents are not part of this output.

The pure Kotlin API is
`DocumentFileExports.text(bookTitle, chapterTitle, paragraphs, format)` in
`com.dongholab.pagetuner.core.content`. `DocumentFileFormat` is `TXT` or
`MARKDOWN`; `DocumentTextFile` contains `filename`, `mimeType`, and `text`.
Platform adapters write the resulting text as UTF-8 without a BOM. The MIME
types are exactly `text/plain` and `text/markdown`, respectively.

## Titles, paragraphs, and text format

Trim only ASCII space, TAB, CR, and LF from both ends of each title. An empty
book title becomes `Untitled`. Omit the normalized chapter title if it is empty
or exactly equals the normalized book title, including the fallback title.
Keep internal title whitespace and all other Unicode whitespace unchanged.

For TXT, the header is the book title followed, when present, by LF and the
chapter title. For Markdown, the header is `# ` plus the escaped book title,
followed, when present, by two LFs and `## ` plus the escaped chapter title.

For both formats, append two LFs, the ordered paragraphs joined with two LFs,
and one final LF. With no paragraphs or one empty paragraph this still appends
three LFs after the header. Keep empty paragraphs and all original paragraph
whitespace, line endings, order, and Unicode. Only separators generated by the
exporter use LF. There is no body trimming, normalization, or truncation.

In Markdown, prefix every ASCII punctuation character in titles and paragraphs
with a backslash: U+0021–U+002F, U+003A–U+0040, U+005B–U+0060, and
U+007B–U+007E. This makes markup, HTML tags, entities, and link syntax in the
source ordinary prose. Markdown renderers can still interpret preserved
whitespace (for example indentation or trailing spaces); this is a readable
copy, not a lossless Markdown round trip or a rendering-equivalence promise.

## Validation and bounds

All bounds are inclusive and measured in UTF-16 code units, matching Kotlin
`String.length` and JavaScript `string.length`, rather than UTF-8 bytes:

- At most 100,000 paragraphs.
- At most 5,000,000 input units across both raw titles and every raw paragraph.
  Count titles before trimming, omitting duplicates, or applying the fallback.
- At most 12,000,000 output units, including escaping, headings, separators,
  and the final LF.

Reject unpaired UTF-16 surrogates in either title or any paragraph. Reject
U+0000–U+001F except TAB (U+0009), LF (U+000A), and CR (U+000D), and reject
U+007F–U+009F. Other Unicode, including bidirectional formatting in the document
body, remains unchanged. Reject invalid or oversized input explicitly before
writing a file; never replace invalid text or silently truncate body text.
Kotlin reports these errors with `IllegalArgumentException`; platform adapters
surface a useful export error and must not report a successful save.

## Safe suggested filenames

`DocumentFileExports.safeFilename(bookTitle, chapterTitle, extension)` shares
the title normalization and validation above. For this helper, count only the
two raw titles against the input limit. The extension must be exactly `txt`,
`md`, or `pdf` without a leading period; all other values are rejected.

1. Start with the normalized book title. If the normalized chapter is present,
   append ` - ` and the chapter title.
2. Replace each of the following code units with one underscore: `<>:"/\|?*`,
   U+0000–U+001F, U+007F–U+009F, U+061C, U+200E–U+200F,
   U+202A–U+202E, and U+2066–U+2069. Invalid source controls are rejected by
   validation first; the allowed TAB/CR/LF are still replaced here.
3. Remove ASCII dots and spaces from both ends, truncate to at most 120 UTF-16
   units without splitting a surrogate pair, then remove edge dots and spaces
   again. If empty, use `document`.
4. Inspect the component before the first period, after removing trailing ASCII
   spaces and converting to uppercase. If it is a Windows device name (`CON`,
   `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`, or `COM`/`LPT` followed by one
   character from `123456789¹²³`), prefix an underscore. Apply the same
   120-unit truncation and edge-dot/space trimming again.
5. Append a period and the extension. The extension does not count toward the
   120-unit stem limit. No deduplication suffix is added by this contract.

These are filename suggestions; platform file pickers decide the destination
and collision behavior. PDF adapters may use this naming helper for a verified
copy of original PDF bytes. This does not add PDF generation to the text API:
a PDF without a verified original byte payload is not a TXT/Markdown conversion
source or a newly generated PDF export.

## Shared vectors

`fixtures/document-file-export-v1/vectors.json` contains exact text output cases
with `name`, `bookTitle`, `chapterTitle`, `paragraphs`, `format`, and
`expected: { filename, mimeType, text }`. `filename-vectors.json` contains
`name`, both titles, `extension`, and the expected filename string.
`rejected-vectors.json` contains invalid text inputs in the text-vector input
shape, with no expected result. Kotlin and web tests consume the same UTF-8
JSON fixtures. Runtime tests cover large bounds without multi-megabyte fixture
files.
