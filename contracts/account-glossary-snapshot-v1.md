# Account glossary snapshot in portable ZIP v1

S4c1 adds passive `extensions.accountGlossarySnapshots` without replacing the legacy ID-less `glossary` array, document provenance, local copy IDs or unrelated extension fields. It is neither an account binding nor a synchronization operation. Import/re-export preserves the snapshot but never adopts it into an account store, creates a mutation, uploads or deletes data.

The extension is exactly `{version:1,snapshots:[...]}`. Each snapshot is exactly `{providerId,bookId,targetLanguage,state,entries}`. At most 16 unique exact provider/book/target-language scopes, in preserved array order. Each scope must match the document's verified original provider/book identity; translations also require their actual targetLanguage. Originals require an explicitly selected target language when creating a new snapshot. Display titles and local copy IDs cannot supply source identity.

`state` is PRESENT, ABSENT or DELETED. PRESENT includes the complete ordered entry array, including an intentionally empty array. ABSENT and DELETED require JSON null entries and remain distinct. At export time the read-only account query's version=0/null is ABSENT, positive version/null is DELETED; any non-null entries are PRESENT. This temporary classification does not serialize the server version, timestamps, CAS/outbox/mutation data or credentials. Format version 1 is independent of synchronization version.

Each entry has every field: `{id,sourceTerm,translatedTerm,displayTerm,kind,caseSensitive,enabled}` with original opaque IDs and exact text. Existing book-glossary-v1 limits apply: maximum 500 entries per scope, IDs 1..200 UTF-16 units, terms 1..200, display text 0..200, kinds Character/Place/Term. Duplicate source terms with different IDs are valid; duplicate IDs are invalid. No trimming, sorting, deduplication, truncation or alias removal occurs. Identity providerId is 1..100, bookId 1..2000; target language follows the concrete lowercase 2..24 character grammar. Unicode and boundary whitespace validation follow book-glossary-v1.

The whole merged extensions object must fit the exchange format's 256KiB UTF-8 limit and passive-metadata rules; a snapshot fitting by itself is insufficient. Strict interpretation rejects unknown/missing/duplicate fields, invalid states/types/Unicode and mismatched scopes. Generic legacy ZIP import may retain unrecognized passive extensions without treating them as trusted snapshots. When adding a scope, replace that exact existing scope in place; append a new scope while preserving all other scopes/extension fields. Do not silently drop an unsupported/malformed existing snapshot to make an export fit.

## Explicit current-account export

The new export action verifies complete document identity against the selected account's owned server record and uses the existing read-only glossary query (`POST /api/v1/book-glossary/query` transport). It reads the current server result for the explicit scope and aborts on verification/query failure or account/client/document/target changes. A cached remote value or local queued/pending/conflicted edit is not represented as the latest server value. Regular offline export remains available separately.

No query or snapshot creation writes a progress/note/classification/glossary row. Saved device annotations remain device records. Snapshot serialization excludes account IDs/origins, authorization, server version, mutation IDs, outbox contents and conflict state. Matching and importing the file never automatically connects or writes account records.

Fixtures in `fixtures/account-glossary-snapshot-v1` preserve original document identity, a legacy device glossary, unrelated passive vendor metadata, duplicate source terms, disabled entries, aliases, empty snapshot and absent/deleted snapshots across exact target-language scopes. Tests must cover actual ZIP write/read/re-export as well as malformed metadata, merged byte limits and stale async export responses.
