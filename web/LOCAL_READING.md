# 로컬 문서와 읽기 기록

기기 보관함의 **로컬 파일**에서 TXT, Markdown, EPUB, PDF를 가져온다. 서버에 업로드하지 않으며 `ReadingDocument.kind = local`로 취급한다. 서버의 원문/번역 artifact를 만들어 내지 않는다.

## 가져오기 범위

- 파일 최대 32MB. 원본 바이트의 SHA-256이 문서 ID다. 같은 내용을 이름만 바꿔 가져와도 중복되지 않는다.
- TXT/Markdown은 BOM UTF-16 또는 엄격한 UTF-8을 기본으로 읽는다. EUC-KR, GB18030, Shift-JIS, Windows-1252 등은 사용자가 선택한다. 잘못된 바이트를 대체 문자로 조용히 넘기지 않는다.
- Markdown은 앱과 같은 기본 텍스트 정규화 범위다. HTML을 실행하거나 원본 스타일을 재현하지 않는다.
- EPUB은 OPF spine 순서대로 XHTML 본문을 읽고 장별 목차를 만든다. 압축 해제 최대 64MB, 항목당 8MB, 4,000개 항목으로 제한한다. 외부 엔터티, 압축 경로 이탈, script/iframe/object/SVG를 실행하지 않는다.
- EPUB 삽화는 장별 첫 두 PNG/JPEG/GIF/WebP만 보관한다. 개별 2MB, 합계 20MB를 제한하고 파일 signature와 Blob 형식을 확인한다. 읽기 도구의 삽화 탭에서 object URL로 표시하며 화면을 떠날 때 해제한다. 외부 URL 이미지를 가져오지 않는다.
- PDF는 최대 2,000페이지다. 원본 Blob을 보관하고 PDF.js canvas로 표시하므로 텍스트 없는 스캔 페이지도 읽을 수 있다. 이전/다음, 페이지 맞춤, 너비 맞춤, 버튼식 페이지 안 위/아래 이동이 있다. 암호 PDF는 먼저 암호를 해제하도록 안내한다.
- PDF 텍스트는 추출 가능한 페이지에서만 얻는다. 이미지 PDF에 OCR을 수행하지 않는다. 서버 번역은 `onTranslate` 연결을 통해 실제 텍스트만 업로드하며, 이미지 페이지를 나타내는 리더용 라벨과 Blob은 제외한다. 본문 검색도 실제 추출 텍스트에서만 수행한다.
- 전체 추출 텍스트는 500만 문자, 일반 텍스트 문단은 5만 개 이하다. EPUB 원본 CSS 배치, 표/수식의 완전한 재현을 약속하지 않는다.

## 저장과 읽기 도구

`deviceReadingDatabase.ts`의 IndexedDB는 계정 이름과 문서 ID로 나뉜다. 로컬 파일, 북마크/메모, 마지막 읽은 위치를 서로 다른 object store에 저장한다. 비밀번호/API 키는 포함하지 않는다. 이는 기기 내 구분이며 데이터 암호화나 서버 동기화가 아니다.

북마크와 메모는 페이지 번호 대신 실제 문단 ID·UTF-16 문자 위치를 저장한다. 글자 크기/화면 변화 후에도 해당 위치를 찾아간다. PDF는 원본 페이지에 대응하는 문단 ID를 사용한다. 메모는 현재 위치의 발췌와 사용자 내용을 보관한다.

텍스트 리더에서 최대 4,000자를 선택한 뒤 `선택 강조`를 누르면 시작·끝 문단 ID와 UTF-16 범위를 보관한다. 저장/읽기 시 발췌가 실제 본문과 일치하는지 확인하며 서로 겹치는 강조는 화면에서 병합한다. 글자 크기와 줄바꿈이 달라져도 본문 위치를 기준으로 다시 표시한다. PDF canvas에는 텍스트 선택 계층이 없으므로 범위 강조를 제공하지 않는다.

읽기 도구의 강조 탭에서 발췌를 읽고 해당 위치로 이동하거나 삭제할 수 있다. 내보내기·공유 탭은 현재 문서의 북마크·강조·메모를 본문 순서로 TXT 또는 `pageturner.reading-notes.v1` JSON 파일로 만든다. 명시적인 공유 버튼은 브라우저가 지원할 때 Web Share를 열며 미지원/실패 시 TXT 다운로드를 안내한다. 계정 이름·원본 Blob·비밀번호를 내보내기에 넣지 않는다. JSON 내보내기는 현재 가져오기/서버 동기화 계약이 아니다. Web Share는 [사용자 활성화와 브라우저 지원](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)이 필요하며, 운영체제마다 완료 신호가 달라 공유 화면에 전달한 것으로 안내한다.

읽기 도구에는 본문 검색과 독서 설정이 있다. 검색어를 정규식으로 실행하지 않고 문자 그대로 찾으며, 원본 UTF-16 offset을 보존해 결과의 문단/페이지로 이동한다. 500개를 넘는 결과는 제한을 알리고 더 구체적인 검색을 요청한다.

글자 크기·명조/고딕/고정폭·행간·여백, 키 기본/반전/비활성, 터치 방향과 목록 paged/scroll 선택은 계정별 localStorage에 저장한다. 저장이 실패하면 이전 설정을 유지하고 오류를 표시한다. 손상된 설정은 명시적인 기본값 초기화로 복구한다. 목록 스크롤은 사용자가 선택해야 활성화되고 본문은 항상 페이지 방식이다. Fullscreen API는 사용자의 버튼 조작으로 진입/해제하며 브라우저/OS가 지원해야 한다.

로컬 서재의 찾기·정렬 화면은 제목/파일 형식/폴더/태그 검색, 폴더 및 즐겨찾기 필터, 최근/제목/폴더 정렬을 제공한다. 각 파일의 분류 화면에서 폴더, 쉼표로 나눈 태그, 즐겨찾기를 편집한다. 분류는 문서 본문·해시·읽기 기록과 분리하며 다시 가져와도 보존된다. 서버 서재 메타데이터의 기기 간 동기화는 아니다.

로컬 원문 보기의 서버 번역 버튼은 10,000문단·100만 문자 한도에서 `ReadingDocument`의 실제 문단 ID를 보존해 앱 상위 흐름으로 전달한다. 업로드·인증·번역 작업 시작은 서버/workflow 계약을 사용한다. 파일 보관만으로 서버에 원문이 전송되지는 않는다.

저장은 트랜잭션 성공 이후에만 완료로 처리한다. 동시 창에서 새 메모를 추가해도 다른 메모 목록 전체를 덮어쓰지 않는다. 원본 파일 ID에 서로 다른 파싱 결과를 덮어쓰지 않으며 기존 기록을 확인한 뒤 명시적으로 삭제하고 다시 가져오도록 안내한다.

저장 문서의 본문/목차와 Blob checksum을 확인한다. 손상된 문서 한 개가 정상 책을 숨기지 않도록 정상 목록과 손상 식별자를 분리하고 삭제 경로를 제공한다. 파일 삭제 확인은 그 파일의 북마크·메모·진행도 함께 삭제됨을 알린다.

## 의존성과 검증

PDF.js `5.5.207` legacy build를 사용한다. Node 20 및 현재 웹 지원 범위와 호환되며 도입 시점 npm audit는 0 vulnerabilities였다. 확인된 `>=5.6.83 <6.2.108` advisory 범위는 사용하지 않는다. 내장 worker, CMap, 기본 글꼴, wasm은 Vite의 동일 origin `/assets`로 배포되고 기존 PWA 정적 manifest에 포함된다.

패키지 사용 근거: [Mozilla PDF.js](https://mozilla.github.io/pdf.js/getting_started/), [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/), [fflate](https://github.com/101arrowz/fflate), [xmldom](https://github.com/xmldom/xmldom).

회귀 테스트는 파일 해시/인코딩/취소, EPUB spine·외부 콘텐츠·압축 제한, 계정 격리·중복·손상 분리, 메모 동시 추가·위치 검증·저장소 재시도를 다룬다. PDF 테스트는 실제 PDF.js로 생성된 PDF의 텍스트를 추출하고 텍스트 없는 페이지를 실제 canvas에 그려 픽셀을 확인한다. 테스트 통과는 모든 PDF/EPUB 파일의 호환성을 뜻하지 않는다.
