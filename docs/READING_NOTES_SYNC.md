# 서버 원문·번역의 북마크·메모·강조 동기화

2026-09-30 최종 검증, 작업 큐 S2. 공통 계약은 [reading-notes-v1](../contracts/reading-notes-v1.md), 다음 범위는 [작업 큐](AGENT_WORK_QUEUE.md)에 있다.

## 지원 범위

- 같은 서버·계정의 원문 또는 완성 번역 record UUID를 기준으로 항목 UUID와 문단 ID·UTF-16 문자 범위를 공유한다. 원문과 번역문은 서로 다른 위치 공간이다.
- 웹의 서버 원문·번역 리더와 해당 서버 ID를 유지한 기기 보관본에 연결한다. 읽기 도구에서 북마크·메모 추가, 제목·메모 수정, 삭제, 강조 목록, 동기화 상태와 충돌 선택을 제공한다. 본문에서 선택한 정확한 범위로 강조를 만든다.
- Android는 서버 서재에서 직접 연 원문·번역에 연결한다. 페이지를 탐색하는 기존 리더와 서버 문단·문자 범위를 보존하는 기록 저장소를 구분한다. 다른 플랫폼에서 받은 여러 문단에 걸친 강조도 원래 범위를 유지한다.
- 로컬 파일·PDF·EPUB·ZIP 사본의 서버 식별자 대응은 S4다. 기존 비UUID 기록과 정확한 범위가 없는 강조는 임의로 이름을 바꾸거나 업로드하지 않는다. 기존 로컬/ZIP 메타데이터를 보존한다. Android의 새 계정 기록은 전용 journal에 있으며 기존 ZIP 재출력에 자동 합쳐지지 않는다. 이전 기기 기록은 별도 전환으로 계속 열 수 있다.

## 보존과 충돌

웹은 기존 기기 보관 DB를 v3로 올리고, 화면 기록과 outbox를 하나의 IndexedDB 트랜잭션에 저장한다. Android는 계정·서버·문서별 AtomicFile journal에 기록과 대기 변경을 보관한다. 응답 유실 후에는 같은 mutation ID와 내용을 재전송한다. 그동안 발생한 새 편집은 별도로 보존한다.

서버는 항목별 예상 version을 비교하고, 다른 클라이언트가 먼저 바꿨으면 409와 현재 기록을 반환한다. 두 내용 또는 삭제 상태를 보존한 뒤 사용자가 직접 선택한다. 편집·삭제 확인·충돌 선택 도중 새 변경이 들어온 경우에도 이전 화면의 선택으로 새 기록을 지우지 않도록 비교한다.

삭제도 version이 있는 표식으로 남는다. 처음 생성되기 전에 삭제한 항목도 표식을 만들 수 있어 오래된 오프라인 생성이 되살리지 못한다. 삭제된 기록을 복원하려면 해당 표식의 version에 대한 명시적인 수정이 필요하다. 제품에 별도 휴지통 화면은 제공하지 않는다.

문서별 증가 revision과 불변 변경 이력을 사용한다. 조회 첫 페이지에서 고정 watermark를 정하고 마지막 페이지까지 같은 경계를 읽는다. 같은 항목의 여러 version이 한 페이지에 올 수 있다. 클라이언트는 기록 적용과 cursor 전진을 함께 저장하며, PUT 응답만 보고 cursor를 건너뛰지 않는다. 오래된 GET·PUT 응답은 최신 항목을 되돌리지 않는다.

계정 세션이 열려 있으면 리더를 닫아도 대기 변경을 재시도하고, 재로그인 후 남은 변경을 재개한다. 열린 책은 주기적으로 원격 변경을 받는다. 앱/브라우저 프로세스가 종료된 동안 실행되는 OS 백그라운드 서비스는 아니다. 인증 실패·문서 삭제·잘못된 응답 등 영구 오류는 명시적 재시도나 재연결까지 보류하며 Retry-After를 존중한다.

## 계약과 검증

- 요청: Basic 인증과 CSRF, 엄격한 JSON·Unicode·UTC timestamp, PUT 32 KiB, 계정별 분당 120회 제한.
- 응답: 서버가 원문 또는 번역의 실제 내용을 기준으로 excerpt를 계산한다. 강조는 끝이 배타적인 정확한 범위이며, 일반 인용문은 최대 1,000 UTF-16 단위에서 surrogate pair를 나누지 않는다. 최대 100항목 조회와 클라이언트 8 MiB 응답 제한을 사용한다.
- 서버: 2026-09-16 격리 PostgreSQL에서 전체 115개 테스트 통과, 신규 16개 포함. V9 migration, 소유권·CSRF·본문 제한·UTF-16·동시 CAS·commit revision 순서·고정 watermark·삭제/복원·cascade를 검사했다. 이후 서버 구현 변경 없음.
- 웹: 2026-09-30 `npm run verify`로 8개 OpenAPI 생성 계약, TypeScript, 프로덕션 빌드와 전체 276개 테스트(37개 파일) 통과. S1 이후 신규 27개는 v2→v3 기존 DB 보존, 화면 기록/outbox의 원자성, 응답 유실 재시도, 삭제 충돌·복원, 고정 watermark, 계정 격리, 늦은 응답, 오래된 편집·삭제·충돌 선택 거부, 응답 스트림 단절과 최초 저장소 연결 실패 후 복구를 검사한다.
- Android: 2026-09-30 `:app:testDebugUnitTest :app:assembleDebug :app:lintDebug :app:compileDebugAndroidTestKotlin` 성공. 92개 suite에서 337개 통과, 기존 opt-in 15개 제외, 실패/오류 0. S2 동기화 17개와 HTTP 7개를 포함한다. lint 오류 0, 경고 75, 힌트 4. 신규 목록·상세의 76dp/100dp 벤치마크 등록 및 instrumentation 소스 컴파일을 확인했으며 실기기 실행은 V3에 남긴다.
