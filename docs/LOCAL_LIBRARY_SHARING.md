# 폰 서재의 로컬 웹 공유

폰과 다른 기기가 같은 Wi-Fi 또는 폰의 핫스팟에 연결되면, 폰에 저장한 책을
다른 기기의 브라우저로 읽는다. 폰이 웹 UI와 API를 모두 제공한다. 인터넷 서버,
회원 로그인, 외부 CDN은 필요하지 않다. 공유는 기본적으로 꺼져 있고 사용자가
설정에서 직접 시작한다. Android Compose 화면과 React 화면은 각 플랫폼에
남기되, 웹 리더를 클라우드용과 폰 공유용으로 복제하지 않는다.

## 사용 흐름

1. 읽을 책과 필요한 번역을 앱에 미리 저장한다.
2. 시스템 설정에서 핫스팟을 켜고 다른 기기를 연결하거나 같은 Wi-Fi를 사용한다.
3. 앱 **설정 → 기기 공유**에서 표시되는 사설 주소를 선택해 공유를 시작한다.
4. PC/태블릿 브라우저에서 앱에 표시된 `http://주소:8787/`를 열고 8자리 코드를 입력한다.
5. 공유 서재에서 책을 읽는다. 앱 화면이나 지속 알림의 중지 버튼으로 끝낸다.

공유는 최대 2시간 유지되며 서비스 종료와 주소 변경에도 중지한다. 다음에
공유할 때는 새 코드가 발급된다. 브라우저의 독서 설정과 읽기 위치는 현재
연결의 메모리에만 있고 폰의 책·읽기 기록·최근 열람 시간을 변경하지 않는다.
HTTP에는 전송 암호화가 없으므로 개인 핫스팟이나 신뢰하는 Wi-Fi에서 사용한다.
비행기 모드에서 핫스팟을 함께 켤 수 있는지는 기기/OS 설정에 달려 있다.

## 핫스팟 연결 시 보이는 화면

핫스팟을 켜는 것만으로 서재 공유가 시작되지는 않는다. 폰의 시스템 설정에서
핫스팟을 켠 뒤 PageTurner **설정 → 기기 공유**에서 공유를 시작한다.
접속할 기기는 해당 핫스팟에 연결하고, 앱에 표시된 실제 주소를 사용한다.
`localhost:5173`은 개발용 웹 주소이며 다른 기기에서 폰 서재에 접속하는 주소가 아니다.

| 단계 | 폰 앱 / 접속 기기에 보이는 내용 |
| --- | --- |
| 폰에서 공유 시작 | 선택할 네트워크 주소, 공유 접속 주소, 8자리 연결 코드와 중지 기능 |
| 다른 기기의 브라우저에서 주소 열기 | ‘휴대폰 서재 공유’ 헤더, 한국어/English 선택, ‘휴대폰의 책을 이 화면에서 읽기’, 연결 코드 입력과 ‘휴대폰에 연결’ 버튼 |
| 코드로 연결 성공 | ‘휴대폰 서재’, ‘휴대폰 공유 · 읽기 전용’, 책 목록, 새로고침·페이지 이동·연결 해제 |
| 책 열기 | ‘휴대폰 공유 · 읽기 전용’ 리더, 원문/번역문 표시, 본문과 이전/다음 페이지. 읽기 도구에서 본문 검색·목차·삽화·독서 설정 제공(목차/삽화는 해당 책에 있는 경우) |
| 저장된 책이 없음 | ‘공유할 수 있는 책이 없습니다.’와 폰에 책을 저장한 뒤 새로고침하라는 안내 |
| 공유 종료 또는 세션 만료 | ‘공유 연결이 끝났습니다.’와 폰에서 공유를 다시 시작하고 연결하라는 안내 |
| 네트워크 연결이 끊김 | 폰에 연결할 수 없다는 오류와 같은 Wi-Fi/핫스팟 연결 확인 안내. 페이지를 새로 열 수 없다면 브라우저의 연결 실패 화면이 먼저 나올 수 있음 |

이 서재는 폰에 저장한 파일·원문·완성 번역을 읽는 화면이다. 클라우드 웹의
WTR-LAB 카탈로그가 그대로 나타나지는 않는다. 폰이 제공하는 웹 자산과 API를
사용하므로 저장한 책을 읽는 데 인터넷 서버가 필요하지 않다. 읽기 위치와
독서 설정은 연결 중에만 유지되며 폰의 기록을 수정하지 않는다.

위 화면 구성은 현재 구현과 기존 공유 HTTP/브라우저 검증을 기준으로 정리했다.
실제 Android 폰의 핫스팟과 다른 물리 기기 간 접속은 아직 미검증이며,
에뮬레이터 실행 성공을 실제 핫스팟 동작 검증으로 간주하지 않는다.

## 모듈과 재사용 경계

| 구성 | 책임 |
| --- | --- |
| `core-sharing` | 플랫폼 의존성이 없는 Kotlin 읽기 DTO·계약 버전·크기 한도 |
| `sharing-runtime` | NanoHTTPD, 페어링·세션, 제한된 GET API, 정적 웹 파일, Host/Origin·경로 검사 |
| Android `sharing` | 기존 세 저장소의 읽기 전용 어댑터, 네트워크 주소 선택, foreground service, 알림·중지 UI |
| `web/src/sharing` | 같은 origin의 폰 API를 소비하는 gateway와 공유 화면 |
| 기존 웹 컴포넌트 | `PagedReader`, `AdaptiveCollection`, `ReaderSearch`, 독서 설정, `LocalPdfReader` 재사용 |
| APK 빌드 | `npm ci` → `build:sharing` → 생성된 `assets/local-sharing` 포함 |

클라우드 웹은 `index.html`과 `sharing.html`이 공통 청크를 사용하는 multi-entry
빌드다. APK는 같은 소스에서 공유 entry만 빌드한다. PDF worker·CMap·글꼴·WASM도
번들에 들어간다. 폰 공유 페이지는 Service Worker를 등록하지 않고 WebCrypto나
IndexedDB를 필수로 사용하지 않는다. 정적 파일은 생성된 웹 자산만 제공한다.

[공통 규격](../contracts/local-sharing-v1.md)과 [OpenAPI](../contracts/local-sharing-v1.openapi.json)에
인증 헤더, 페이지 목록, 문서 및 revision에 고정한 자산 조회를 정의했다.

## 제공 범위

- 앱 로컬 서재: TXT, Markdown, EPUB 본문과 저장된 bitmap 삽화, 원본 PDF.
- 표준 ZIP 보관 서재: 저장된 원문·완성 번역과 PDF/삽화.
- 비행기용 `offline_novels`: 내려받은 웹소설 원문과 저장된 완성 번역.
- 웹 도구: 페이지·키 이동, 텍스트 검색, 목차, 삽화, 글꼴/행간/여백 설정,
  PDF 페이지·너비 맞춤 및 버튼식 페이지 안 이동.

문서의 edition은 저장된 메타데이터로 구분한다. 현재 제공자/모델/용어집 variant를
안전하게 확인할 수 없는 진행 중 번역 캐시를 완성 번역으로 추측해 공개하지 않는다.
클라우드에만 있는 책은 먼저 폰에 저장해야 한다. 공유 모드는 업로드·삭제·번역 실행,
계정 설정이나 메모 동기화를 제공하지 않는다. 기존 ZIP 교환과 계정 동기화는 별도 기능이다.

텍스트 문단 ID와 UTF-16 위치를 보존한다. PDF는 실제 PDF의 물리 페이지에 대응하며
원본 파일 해시로 묶는다. 네이티브 PDF의 화면용 공유 anchor는 기존 텍스트 segment나
계정 동기화 identity를 대체하지 않는다. PDF 공유에서 새 텍스트 추출/OCR은 수행하지
않으므로 텍스트가 없는 PDF의 검색은 제공하지 않는다. EPUB은 기존 parser의 형식·삽화
범위를 따른다(D2의 전체 레이아웃 확장과 별개).

한 문서는 텍스트 400만 UTF-16 문자, 자산 하나 32MiB, PDF 2,000쪽까지다.
Android는 자산 합계 48MiB, 스냅샷 최대 3문서/64MiB를 제한하고 EPUB 압축 해제·
이미지 참조·텍스트 누적에도 별도 한도를 적용한다. 손상되거나 너무 큰 보관 문서는
문제 항목으로 격리해 다른 정상 책의 목록/읽기를 막지 않는다.

## 검증과 남은 실제 환경 검사

이번 변경은 별도 loopback/사설 IP 합성 서재와 테스트 임시 디렉터리에서 검증한다.
기존 미리보기 DB와 사용자 책은 테스트에 사용하지 않는다. 자동 검사·브라우저
검증의 최종 결과는 아래 실행 기록과 작업 큐에 기록한다.

Android 실제 핫스팟 → 다른 물리 기기 브라우저 왕복, 화면을 끈 장시간 서비스,
제조사 절전 정책·알림·네트워크 전환은 연결된 기기가 없어 미검증이다. 비행기에서
동작을 보장했다고 표시하지 않는다. 현재 target36과 향후 target37의 LAN 권한 차이는
[Android LAN 권한 문서](https://developer.android.com/privacy-and-security/local-network-permission),
서비스 유형은 [connectedDevice 문서](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device)를 따른다.
