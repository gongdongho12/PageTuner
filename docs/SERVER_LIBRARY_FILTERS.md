# 서버 서재 검색·분류 필터 (S3b2a)

## 범위

서버에 보관된 원문과 번역본을 제목·폴더·태그·즐겨찾기로 검색한다. Android 서버 서재와 웹의 원문/서버 서재가 같은 조회 계약을 사용한다. 서버는 계정 소유권과 원문/번역 종류를 구분하고 **전체 서재에서 조건을 적용한 뒤** 페이지와 전체 개수를 계산한다. 한 번 불러온 페이지 안에서만 찾는 검색이 아니다.

이는 S3b1의 개별 문서 분류에 대한 조회 기능이다. 소스 사이트의 책 즐겨찾기는 별도 식별자와 삭제·충돌 정책이 필요한 S3b2b로 남는다. 독립 로컬/ZIP 문서 연결은 S4이며 문서 제목으로 같은 책을 추정하지 않는다.

## 조회 계약

`GET /api/v1/chapters`와 `GET /api/v1/translations`의 기존 `page`, `size`에 선택 조건을 추가한다. 조건을 생략하면 기존 최신순 목록을 유지한다.

| 조건 | 의미 |
| --- | --- |
| `q` | 책/장 제목의 대소문자 무시 부분 일치. 최대 200 UTF-16 단위. 빈 값은 검색하지 않음. `%`, `_`, 역슬래시도 문자 그대로 검색 |
| `folder` | 정확한 폴더명. 최대 200 UTF-16 단위. 생략은 전체, 명시적 빈 값은 미분류(분류 기록 없음 포함) |
| `tag` | 정확한 태그 하나. 1–60 UTF-16 단위. 쉼표도 태그명 일부이며 분리하지 않음 |
| `favorite` | 생략은 전체, `true`는 즐겨찾기, `false`는 즐겨찾기 아님(분류 기록 없음 포함) |

여러 조건은 AND로 결합한다. 폴더·태그의 대소문자와 Unicode 값을 보존하고 임의 정규화하지 않는다. 조건은 ECMAScript trim과 같은 양끝 공백 규칙을 따르며 제어 문자와 잘못된 surrogate를 거절한다. 클라이언트는 초안 양끝을 정리하고 서버는 잘못된 요청을 거절한다. `created_at desc, id desc` 정렬과 기존 페이지 크기 제한을 유지한다. 조회는 분류 기록을 만들거나 수정하지 않는다.

## 화면

- Android: 서버 서재의 `서재 검색·필터` 하위 화면에서 제목, 폴더 선택/이름, 태그, 즐겨찾기를 편집한다. 목록은 `AdaptiveCollection`에 남기며 입력 항목도 별도 페이지 컨테이너를 사용한다. 적용/초기화는 첫 페이지로 돌아가고, 종류·계정 변경은 조건과 이전 결과를 비운다.
- 웹: 서버 서재와 보관 원문의 `검색 · 필터` 버튼이 공통 편집 화면을 연다. 작은 화면에서도 입력과 44px 이상 동작 버튼이 함께 보이도록 항목별로 이동한다. 원문 URL 가져오기는 별도 하위 화면으로 이동했다. 적용/초기화는 첫 서버 페이지로 돌아가며 페이지 이동·새로고침에 조건을 유지한다. 실패한 새 조회에 이전 조건의 결과를 보여주지 않는다.
- 조건은 로그인 세션에만 보관한다. 양쪽 클라이언트가 취소된 이전 응답을 거절하며 원문/번역을 섞지 않는다. 개별 문서 분류의 기존 동기화·충돌 처리·독서 위치는 변경하지 않는다.

## 검증 기록 (2026-10-02)

- PostgreSQL 검증은 미리보기 `pagetuner_test`와 분리된 `pagetuner_test_20260915_rolling`에서 실행했다. 서버 152개/25 suite와 공통 모델 7개가 통과했다. 17개 조건 일치 문서의 12개 페이지 경계, count/정렬/AND, 다른 계정·같은 UUID의 원문/번역 격리, 미분류/초기화, 특수문자, Unicode 정확한 태그, 본문을 읽지 않는 projection, 잘못된 조건/인증 검사를 포함한다.
- Android 424개 통과/기존 opt-in 15개 제외(103 suite). APK·lint·계측 소스 컴파일·모듈 경계 검사 성공. lint 오류 0/경고 77/힌트 4. HTTP 인코딩·명시적 빈 폴더·false, 적용/초기화, 실패 후 재시도, 늦은 성공/오류와 종류 전환 회귀를 추가했다. 필터 패널을 포함해 production `AdaptiveCollection` 26개와 대응 벤치마크를 등록했다.
- 실제 HTTP fixture는 별도 8081 서버와 테스트 계정을 사용했다. 원문/번역 각각 30개 중 최신 16개는 조건 불일치, 이전 14개만 조건 일치하도록 만들었다. 네 조건을 함께 적용하면 14개, 두 번째 서버 페이지는 2개, 미분류·즐겨찾기 제외는 16개임을 양쪽 API에서 확인했다. 외부 번역 API는 호출하지 않았다.
- 실제 브라우저에서 번역 30개 → 제목 `100%_\`·폴더·쉼표 태그·즐겨찾기 AND → 14개, 화면 `10–12`에서 다음 서버 목록의 `13–14 / 14` 이동, 같은 조건으로 새로고침, 0개 검색 안내, 초기화 후 `1–3 / 30` 복원을 확인했다.
- 브라우저 검사에서 이전 H1의 배포 회귀를 발견했다. 오프라인 셸 manifest의 `/sharing.html`이 서버에서 401로 막혀 새 셸 설치가 실패했다. 정적 HTML의 GET만 공개하고 API/다른 메서드 보호를 유지했다. 보안 회귀 테스트와 실제 200 응답, 기존 캐시에서 새 worker 설치 대기 → 탭을 닫고 재방문해 최신 bundle 활성화를 확인했다. 캐시나 사용자 데이터를 지워 우회하지 않았다.
- 웹 최종 `npm run verify`: 367개/49파일, 생성 계약 11개·TypeScript·프로덕션 빌드 통과. 원문 미분류+즐겨찾기 제외 16개, 결과에서 원문 읽기와 복귀, 한국어/영어 390×844 검색/편집 화면을 확인했다. 844×390 가로 화면에서 편집 버튼 하단이 11px 잘리던 문제를 단계 표시의 라벨 통합으로 수정했다. 수정 후 폼 하단 378px 안에 모든 44px 버튼이 374px까지 들어가며 정상/검증 오류 모두 입력과 동작에 접근 가능함을 실측했다. 원문 목록 자체는 이처럼 낮은 가로 화면에서 공간 부족 안내를 유지하며 행을 잘라 표시하지 않는다.
- 최종 웹 변경 후 APK 자산을 재생성하고 `assembleDebug` 성공을 확인했다. 별도 fixture 브라우저·8081 서버를 종료했다. 8080 미리보기는 활성 번역 작업 0개와 실행 JAR 경로를 확인한 뒤 새 실행용 JAR 사본으로 갱신했고 health UP, 익명 `/sharing.html` 200을 확인했다. 미리보기 DB에 테스트 정리/fixture 삽입을 실행하지 않았다. 이전 셸은 열려 있는 탭을 닫은 뒤 새 방문에서 업데이트되며 사용자 탭과 읽기 상태는 직접 바꾸지 않았다.
