# 소스 책 즐겨찾기 계정 동기화

작업 큐 S3b2b. 서버 문서 UUID에 붙는 [서재 분류](LIBRARY_ORGANIZATION_SYNC.md)와 별개로, 소스에서 발견한 책을 같은 계정의 Android와 웹에서 공유한다.

## 식별자와 기존 데이터

계정·서버 origin과 원래 소스 API의 `sourceId`/`bookId`를 사용한다. API의 `providerId`는 이 `sourceId`이며, `bookId`는 `NovelSourceService`가 이미 반환하는 식별자다. 현재 웹소설 runtime은 `WebNovelSeriesKeys`의 canonical URI를 사용한다. Android 화면의 `remoteId`(예: `novel_42`), 제목, 서버 문서 UUID 또는 새 URL 해시로 대체하지 않는다. 이 기능을 위해 기존 책·회차·번역 식별자를 변경하지 않는다.

기기 즐겨찾기를 처음부터 계정 목록으로 올리지 않는다. 사용자가 특정 책을 선택해 계정에 연결한다. 계정 목록에서 삭제해도 별도로 보관한 기존 기기 목록을 지우지 않는다. 예전 Android 항목에 실제 provider/book 메타데이터가 없으면 그대로 기기에 남긴다. 상세 정보를 다시 읽어 식별자를 확보한 뒤 명시적으로 연결한다.

## 동시 변경과 연결 장애

항목별 예상 version과 mutation UUID를 사용한다. 삭제도 version이 있는 표식으로 남겨 오래된 오프라인 등록이 자동으로 되살리지 못하게 한다. 충돌은 기기 값과 서버 값을 유지하고 사용자가 선택한다. 늦게 도착한 응답이나 오래된 선택으로 더 최근 편집을 덮어쓰지 않아야 한다.

계정 전체의 불변 변경 이력을 고정 watermark까지 읽는다. 기록 적용과 cursor 전진은 하나의 저장 작업으로 처리하며 PUT 응답만으로 cursor를 건너뛰지 않는다. 전송 중 추가 편집은 응답을 기다리는 변경과 구분하고, 응답 유실 시 같은 mutation ID와 요청을 재전송한다. 로그아웃은 해당 계정의 전송을 멈추되 대기 데이터를 보존한다.

## 검증 기록

- 공통 모델 11개, 격리 PostgreSQL의 서버 164개 검사를 통과했다. 서버 즐겨찾기 검사는 CAS 경쟁·계정 격리·삭제·재전송·watermark 페이지 경계를 포함한다. Spring 테스트 컨텍스트들의 풀 합계가 테스트 DB 연결 한도를 초과하지 않도록 테스트 설정에만 풀 제한을 적용했다.
- Android 442개 통과, 기존 opt-in 15개 제외(106 suite). APK·lint·계측 소스 컴파일·모듈 경계 검사 성공. lint 오류 0, 경고 79, 힌트 4. 계정/책 전환, 오프라인 재시작, 대기/후속 편집, 삭제·충돌, 원본 소스 ID와 화면 ID 분리를 검사했다. 27개 AdaptiveCollection 호출부의 계측 대상 등록도 검사했다.

- 실제 HTTP 클라이언트: 합성 책 54개를 50+4개로 조회했다. 페이지 사이의 변경에도 watermark가 유지됐고, 같은 mutation 재전송·version 2 삭제·오래된 생성의 409·version 3 복원을 확인했다.
- 실제 브라우저: 서버를 중단하고 삭제를 대기시킨 뒤 브라우저를 완전히 닫았다. 별도 클라이언트가 그 책을 version 4로 수정한 다음 재접속하자 양쪽 값을 보존한 충돌 화면이 나왔다. 기기 값을 선택한 뒤 서버 version 5 삭제 표식과 목록 53권을 확인했다. 기존 미리보기 DB는 사용하지 않았다.
- 실제 WTR-LAB 카탈로그의 책을 기기 즐겨찾기에 저장하고, 원래 canonical book ID를 확인한 뒤 한 권만 명시적으로 계정에 추가했다. 계정 목록은 54권으로 동기화됐고 기존 기기 목록도 유지됐다. 계정의 책 열기로 실제 1,539개 목차에 다시 진입했다. 본문 수집·번역 실호출 검증과는 별개다.

## 한계와 다음 작업

Android 물리 장치는 `adb devices`에 없었다. 실기기 동작은 V3이며 단위 검사·APK 빌드로 완료 처리하지 않는다. H1 핫스팟·화면 꺼짐·절전 검증도 여전히 V3다.

v1의 provider ID는 100, book ID는 500 UTF-16 단위 한도다. 더 긴 기존 소스 식별자는 기기에 보존하고 계정 연결을 거절하며 자르거나 새 해시로 대체하지 않는다. 저장 URL은 공유 검증 규칙의 HTTP(S) 주소만 허용하고 이 API가 직접 가져오지는 않는다. 보수적인 DNS/IPv4/IPv6 규칙과 자세한 필드 한도는 [계약](../contracts/source-book-favorites-v1.md)에 명시했다.

기존 웹 기기 즐겨찾기에 없던 저자/언어 정보는 추측하지 않는다(빈 저자, `auto`). 저장된 소스 URL 모음 자체의 동기화, 용어집(S3c), 독립 로컬/ZIP 문서 대응(S4)은 이 작업의 완료 범위에 포함하지 않는다.
