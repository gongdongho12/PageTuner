# 계정 읽기 설정 동기화

2026-09-30, 작업 큐 S3a. [공통 계약](../contracts/reader-preferences-v1.md), [작업 큐](AGENT_WORK_QUEUE.md).

## 범위와 사용 흐름

같은 서버·계정에서 글자 크기, 행간, 페이지 여백, 터치 방향, 목록 표시를 공유한다. 웹의 **읽기 도구 → 독서 설정 → 계정 설정 동기화**, Android의 **Settings → 계정 독서 설정**에서 기기/서버 값을 비교한다. 첫 연결 시 사용할 값을 직접 선택한 뒤부터 변경과 원격 조회를 자동 동기화한다. 로그인·화면 열기만으로 기존 값을 업로드하지 않는다.

공통 범위는 글자 크기 14–36, 행간 110–240%, 여백 0–48이다. CSS px와 Android sp/dp는 논리 단위이며 기기별 물리 크기·줄바꿈이 완전히 같다는 뜻은 아니다. 행간은 정수 백분율로 저장해 부동소수점 반올림 차이를 줄인다. 본문은 목록 스크롤 설정과 관계없이 페이지 방식이다.

웹 글꼴·페이지 키, Android 표시 모드·PDF 맞춤, 계정 언어, 번역 공급자·키·번역 속도는 이 자원에 포함하지 않는다. 계정 언어 API는 기존대로 사용한다. 폴더·태그·즐겨찾기는 S3b, 용어집은 S3c에 남아 있다.

## 저장과 복구

- 서버는 계정별 단일 version 자원을 V10 테이블에 보관한다. 최초 GET은 version 0과 null 값이며 기본 설정을 생성하지 않는다. PUT은 예상 version과 mutation UUID로 비교·저장한다. 최신 동일 요청의 재전송은 version을 늘리지 않는다.
- 웹은 계정별 IndexedDB journal에 화면 값과 pending/queued 변경을 원자적으로 저장한다. 기존 localStorage 설정은 최초 기기 값으로 사용하고 글꼴·페이지 키를 계속 보존한다. 다중 탭의 읽기·수정도 동일 트랜잭션 경계를 사용한다. 종료 직전에 접수한 기기 변경은 저장을 마친 뒤 연결을 닫는다.
- Android는 서버 origin·정규 계정 이름으로 분리한 AtomicFile journal을 사용한다. 기존 DataStore는 기기 기본값이며 활성 계정의 다섯 필드만 화면·리더에 적용한다. 계정 전환 중 이전 계정의 비교 화면과 편집 콜백을 차단하며 로그아웃하면 기기 기본값으로 복귀한다.
- 응답을 받지 못한 요청은 동일 mutation으로 재전송한다. 전송 중 새 편집은 별도 queued 값으로 남긴다. 최신 서버 version을 이전 GET/PUT 응답으로 되돌리지 않으며, 늦은 ACK가 더 최신 서버 변경을 발견하면 충돌을 보존한다.
- 충돌 시 다섯 필드를 하나의 설정으로 비교하고 기기/서버 중 직접 선택한다. 화면을 본 뒤 기기 값 또는 서버 값이 바뀌면 오래된 선택을 거부한다. 자동 병합·기기 우선순위·시각 비교로 덮어쓰지 않는다. 초기화도 같은 규칙의 명시적 값 저장이다.
- 열린 계정 세션에서 화면을 닫아도 전송을 재시도한다. 30초 원격 조회, 일시 오류 재시도, 영속 Retry-After를 사용하며 인증·잘못된 응답·저장소 오류 등은 명시적 재시도 또는 재연결까지 보류한다. 기기 저장 실패는 웹 독서 화면에도 표시한다.

앱 프로세스를 오프라인에서 재시작하면 인증 세션이 없으므로 계정 설정을 즉시 적용하지 않는다. 대기열은 보존되며 온라인 재로그인 후 복구한다. 프로세스가 종료된 동안 실행되는 OS 백그라운드 동기화는 이번 범위가 아니다. 웹은 같은 기기에 보관한 마지막 계정 namespace의 값을 오프라인에서도 읽지만 서버 전송에는 재로그인이 필요하다.

## 실제 실행 기록

- 미리보기 계정에서 첫 로그인·설정 화면 진입 후에도 API가 version 0/null을 반환했다. 기기 설정을 선택한 뒤 글자 22·행간 195%·여백 28이 version 1로 저장됐다.
- 별도 HTTP 클라이언트가 글자 19·행간 110%·여백 0으로 저장한 version 2가 웹에 자동 반영됐고 편집 화면의 슬라이더도 동일하게 바뀌었다. 이는 같은 계약의 별도 클라이언트 검증이며 Android 실기기 조작을 대신하지 않는다.
- 390×844에서 최초 기기/서버 비교 두 행이 함께 표시됐고 버튼은 44px, 문서 크기는 390×844로 넘침이 없었다. 각 행의 외부 예약 높이는 168px이며 테두리를 제외한 내부는 약 167px였다.
- 정상 연결 중 웹 슬라이더의 글자 변경이 version 4(25), version 6(28)으로 서버에 저장됐다. 활성 작업 0건을 확인하고 미리보기 서버를 중단한 뒤 글자를 29로 바꾸자 전송 오류와 함께 기기 29/서버 28을 유지했다. 사이트를 닫은 뒤 서버를 재시작하고 별도 HTTP 클라이언트로 version 7(글자 21)을 저장했다. 웹 재로그인 후 영속 pending을 재시도하면서 기기 29/서버 21 충돌을 표시했다.
- 충돌 화면의 서버 설정을 선택하자 양쪽 글자 21·행간 110%·여백 0과 동기화 완료를 표시했다. API는 version 7을 유지해 이 선택으로 서버 값을 다시 덮어쓰지 않았음을 확인했다. 최종 웹 번들 `index-DKcK3W_x.js`에서 검증했다. 로컬 증거: `.gradle-home/reader-preferences-conflict-20260930.jpg`, `.gradle-home/reader-preferences-synced-20260930.jpg`.
- 설정 화면에서 본문으로 돌아오면 28/72쪽에서 14/35쪽으로 재배치되지만 문단 10 시작과 기존 강조가 유지됐다. 본문 실제 CSS는 font-size 21px/line-height 23.1px로 계정 값과 일치했다. 검증 후 임시 390×844 뷰포트를 원래 크기로 복구했다.
- 미리보기 실행 중 JAR가 갱신되어 클래스 로딩 오류가 발생했으나, DB를 읽기 전용으로 확인해 활성 번역 작업 0건을 확인한 뒤 해당 프로세스만 재시작해 복구했다. 로컬 시작 스크립트를 별도 실행용 JAR 사본을 사용하도록 바꿨다. 테스트 DB 정리 작업을 미리보기 DB에서 실행하지 않았다.
