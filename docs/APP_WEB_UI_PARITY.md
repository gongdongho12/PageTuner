# 앱·웹 독서 UI와 서버 연결

웹 컴포넌트는 `/frontend`, Android Compose는 `/app`, 영속 API는 `/server`에 둡니다.
플랫폼 UI 파일을 직접 공유하지 않고 독서 동작과 데이터 계약을 맞춥니다.
웹 공통 동작은 `frontend/src/lib/app-ui-contract.ts`, 서버 클라이언트는
`frontend/src/lib/server-library.ts`에 있습니다.

## 화면과 조작

| 앱의 동작 | 웹 반영 |
| --- | --- |
| 서재와 소스 분리 | 서재 아래 기기 / 서버 / 웹 카탈로그 탭 |
| 리더·검색·책갈피·메모 하위 화면 | ReaderPanel의 개별 탭. 책 정보도 별도 탭 |
| 화면·페이지 이동 / 독서 설정 / AI 번역 | SettingsPanel의 독립 탭. 웹 서버 연결은 별도 탭 |
| 페이지 버튼이 기본인 목록 | 기기·서버 서재와 챕터·책갈피에 AdaptiveCollection 사용 |
| 사용자가 선택한 터치 스크롤 | 목록에만 적용. 리더 본문은 항상 페이지 이동 |
| 좌우 터치, 반대 방향, 버튼만 사용 | 공통 tapAction 정책. 가운데 20%로 집중 읽기 종료 |
| 방향키·PageUp/Down·Space | 키·터치·버튼이 공통 turn 처리. Shift+Space는 이전 |
| 읽기 기본값 | 글자 18, 줄 간격 1.35, 여백 18, 번역문 표시 |
| 화면 변경에도 읽기 위치 유지 | PagedText가 문자 앵커로 재배치 위치 계산 |

웹 글자 크기 범위 14–28, 줄 간격 1.1–1.8, 여백 8–36은 앱 설정 UI와 같습니다.
이미 저장한 웹 설정은 유지하고, 설정의 '앱 독서 기본값'으로 명시적으로 초기화할 수 있습니다.
브라우저 CSS px와 Android sp/dp의 물리 크기는 각 기기의 배율에 따릅니다.

긴 원문·번역문은 선택 글꼴로 실제 DOM 높이를 측정해 나눕니다. 작은 화면에서는
문서 한 페이지가 여러 화면으로 표시될 수 있습니다. 키나 터치로 다음 화면을 먼저
소비한 다음 문서 페이지를 넘기며, 이전 문서로 돌아갈 때는 마지막 화면에서 시작합니다.
원문과 번역문을 함께 볼 때도 어느 한쪽의 남은 본문을 건너뛰지 않습니다.
집중 읽기에서는 하위 페이지 버튼을 숨기고 같은 키·터치 처리를 유지합니다.

## 서버 서재 사용

1. 설정 → 서버 연결에 서버 계정을 입력합니다(현재 세션에만 유지).
2. 서재 → 서버에서 연결합니다. 브라우저 세션이 이미 있으면 서버 서재를 바로 엽니다.
3. 기기에서 열었던 책은 서버 탭의 저장 버튼으로 업로드합니다. 실제 원문 언어를 입력합니다.
4. 서버 책 → 챕터 또는 이어 읽기로 본문을 엽니다.
5. 읽기 위치는 챕터 ID·문단 ID·원문 문자 오프셋으로 저장합니다.
6. 리더의 책갈피 화면에서 현재 위치와 메모를 저장하거나 기존 책갈피로 이동합니다.

업로드는 추출된 텍스트만 보내며 PDF 원본 바이너리를 포함하지 않습니다. 텍스트가 없는
이미지 PDF는 원문 업로드를 거부합니다. 같은 책 등록을 반복하면 별도 서버 책이 생기므로
기존 서버 책은 목록에서 다시 여세요. 웹 로컬 책을 서버 책으로 교체하지 않습니다.

서버 번역 읽기는 동일 원문 revision·대상 언어의 최신 저장본을 가져옵니다. 번역 공급자와
모델을 리더에 표시합니다. 현재 웹 번역 설정과 다른 저장본일 수 있으며, 번역이 없는
문단은 원문을 표시합니다. 서버 리더에서 자동 번역 요청을 실행하지 않습니다.

## 진행률과 충돌

진행률 쓰기는 순서대로 보내며 이전 응답의 version을 다음 요청에 사용합니다.
탭을 떠나도 이미 예약한 쓰기는 해당 책 ID로 마무리해 마지막 위치가 유실되지 않게 합니다.
해제된 UI에는 응답을 적용하지 않습니다. 서버가 409를 반환하거나 네트워크가 실패하면
후속 자동 쓰기를 멈춥니다. 사용자는 서버 위치로 이동하거나 현재 위치를 저장할 수 있습니다.
서버의 새로운 version을 조회한 뒤 명시적인 선택에 따라 처리합니다.

번역문만 보는 경우에는 원문과 문자 길이가 다르므로 문단 단위로 이어 읽습니다.
원문 화면은 문단 내 문자 위치까지 저장합니다. 기기 서재의 로컬 진행률은 기존 페이지
기준이고 서버 서재는 문단 앵커 기준입니다. Android 기기의 서버 동기화는 별도 연결 작업입니다.

## 검증과 남은 차이

- `tests/app-ui-contract.test.ts`: Android 기본값·범위와 웹의 일치, Unicode 분할,
  문자 앵커 재배치와 터치·키 정책.
- `tests/server-library.test.ts`: UTF-16 보존 업로드, 인증·CSRF 순서,
  연속 진행률 저장과 충돌 후 중단.
- `tests/e2e/server-library.spec.ts`: 데스크톱·모바일에서 실제 DOM 페이지 이동,
  API 계약 기반 진행률·책갈피·충돌 선택과 집중 읽기. API 응답은 격리된 fixture로 대체.
- 서버 PostgreSQL 통합 테스트는 별도로 실제 저장·소유자 격리·동시성·CSRF를 검증.

앱의 등장인물 사전, 하드웨어 볼륨 버튼, 진단 로그, PDF 전용 맞춤 모드와 WTR-LAB 전용
수집 기능을 웹에서 모두 제공하는 것은 아닙니다. 웹에 없는 기능의 탭을 동작하는 것처럼
추가하지 않습니다. 지원하는 독서 동작과 서버 데이터 흐름부터 일치시킵니다.
