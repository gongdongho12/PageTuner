# 책별 용어집 계정 동기화

작업 큐 S3c. 공통 계약·서버·Android·웹 연결과 로컬/실제 웹 검증을 구현했다. [draft PR #32](https://github.com/gongdongho12/PageTuner/pull/32)는 PR #31 위에 쌓으며 자동 병합하지 않는다.

## 보존하는 정보

계정·서버 origin·원래 provider/book 식별자·대상 언어를 키로 사용한다. 서버 원문과 번역은 같은 원본 책 키를 공유한다. Android 로컬 bookId, 서버 문서 UUID, 제목을 책 식별자 대신 사용하지 않는다. 독립 로컬/ZIP 문서의 자동 대응은 S4다.

전체 ordered entries에서 id, sourceTerm, translatedTerm, displayTerm, kind, caseSensitive, enabled를 보존한다. 기존 파일 교환 codec의 ID 재생성·잘라내기·정렬·중복 제거를 계정 동기화에 적용하지 않는다. 동기화 version과 번역 fingerprint는 별개이며 별칭과 종류만 바꾸어도 계정에는 동기화되지만 번역 캐시는 유지한다.

## 연결과 충돌

기존 기기 용어집은 자동 업로드하지 않는다. 책과 대상 언어를 확인하고 명시적으로 기기 또는 계정 값을 선택한다. 항목 전체 스냅샷에 version/CAS와 mutation ID를 적용하며 삭제도 version이 있는 null 스냅샷으로 남긴다. 계정 선택 뒤 삭제된 사전에서 오래된 기기 사전으로 자동 복귀하지 않는다.

전송 전 영속 대기열에 기록하고, 응답 유실 때 같은 요청을 재전송한다. 충돌의 양쪽 전체 값을 보존하며 오래된 화면의 선택이 새로운 편집을 덮어쓰지 않도록 검증한다. 계정·책·언어 전환 후 늦은 응답과 저장 오류도 표시한다.

계정 선택과 전송 대기열의 연결은 구분한다. 기기 용어집으로 돌아가도 이미 수락한 계정 편집은 백그라운드에서 전송한다. Android는 AtomicFile, 웹은 IndexedDB에 저장한다. 저장소 손상을 빈 사전으로 간주해 업로드하지 않는다. Android 편집은 해당 제출의 완료 결과를 확인한 뒤에만 초안을 닫는다.

## 저장과 번역 실행의 한도

계정 스냅샷은 최대 500항목이다. 웹 번역 workflow의 최대 200개 활성 항목 한도는 저장 한도와 별개다. 허용 범위를 넘으면 원본 스냅샷을 보존하고 실행을 거절하며 항목을 조용히 잘라내지 않는다. 기존 ID 없는 workflow 요청의 식별 규칙은 유지하고 계정 항목은 명시적 ID로 전달한다.

원본 provider ID 100자·book ID 2,000자와 항목 ID 200자를 지원한다. 긴 CJK 식별자는 URL 요청 줄 한도를 넘을 수 있으므로 클라이언트 조회는 CSRF가 적용된 읽기 전용 POST query를 사용한다. PostgreSQL은 내부 identity hash를 인덱스에 사용하되 전체 원본 identity도 비교한다. PUT 전체 UTF-8 JSON은 1MiB 이내여야 하며 초과 입력은 대기열에 넣기 전에 거절한다. 원문/번역 용어는 각 200자, 별칭은 0~200자다. 파일 교환 codec의 별도 표현 한도는 계정 동기화 규격과 다르다.

## 검증 기록

2026-10-03, 격리 PostgreSQL `pagetuner_test_20260915_rolling`와 8081 테스트 서버를 사용했다. 기존 8080 미리보기 DB에는 테스트 fixture 삭제를 실행하지 않았다.

- 공통 모델 15개, 서버 177개/27 suite, 웹 404개/54파일, 생성 계약 13개가 통과했다. 서버 JAR·웹 프로덕션/공유 셸·모듈 경계 검사를 통과했다.
- Android 460개 통과/기존 외부 opt-in 15개 제외(109 suite), APK·lint·계측 소스 컴파일 성공을 확인했다. lint 오류 0/경고 79/힌트 4다. 최종 CI는 작업 큐와 PR 검사에 남긴다. HTTP/actor 테스트는 원래 식별자, ordered fields, 삭제, 응답 유실과 queued 편집, 계정 전환, 파일 복구, 크기 초과 후 정상 편집을 포함한다.
- 실제 HTTP: provider 100 CJK자·book 2,000 CJK자·항목 ID 200 CJK자·500항목을 POST/PUT으로 왕복했다. 필드와 순서를 비교했으며 부재 조회, mutation 재전송, CAS 409, 대상 언어 격리, tombstone/복원도 확인했다.
- 실제 Google Web 번역: 합성 영어 원문 2문단에 활성 2항목을 전달했다. 원래 항목 ID가 job settings에 남고 결과의 `앨리스`, `강 마을` 및 `protected-terms-v1:2b9a997efd3d6798` 식별자가 일치했다. 비활성 항목은 전체 계정 스냅샷에 보존했다.
- 실제 웹: 최초 계정 선택, 원문/번역에서 같은 ko 범위, 별칭 표시, 별칭·종류 수정, 새 항목의 대소문자/비활성 저장, 항목 삭제와 전체 tombstone/원격 복원을 확인했다. 서버 readback으로 원래 ID·순서·공백·다른 항목이 유지됨을 비교했다.
- 오프라인에서 별칭을 바꾸고 브라우저를 닫은 뒤 다른 HTTP 클라이언트로 수정했다. 재로그인 후 `오프라인 앨리`와 `원격 앨리`를 각각 비교할 수 있었고 기기 선택으로 version 6에 저장됐다. 계정→기기 모드 복귀 후 리더에서 계정 별칭이 해제되는 것도 확인했다.
- 390×844와 844×390의 목록·비교 페이지 및 한/영 문구를 확인했다. 목록은 사용 가능한 높이에 따라 완전한 행만 배치하고 나머지는 다음 페이지로 이동한다.

Android 연결 장치가 없어 물리 기기·핫스팟·화면 꺼짐/Doze는 V3에 남긴다. 유료 제공자 실호출은 V2, 독립 로컬/ZIP 문서 대응과 새 서버 기록의 ZIP 통합은 S4다. 기존 파일 교환 JSON과 조사·강조 선택까지의 전체 화면 회귀는 V1의 별도 검증 범위로 남긴다.
