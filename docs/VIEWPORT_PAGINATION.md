# 화면 높이에 맞춘 목록과 본문 페이지 (U1)

2026-10-02. `codex/viewport-pagination`, base `codex/library-organization-sync`(PR #27).

## 구현 범위

- Android·웹 목록의 유한 높이에서 최대 8행 제한을 제거한다. 실제 행·간격·페이지 버튼 높이를 예약하고 온전히 들어가는 행만 표시한다. Android는 물리 픽셀 반올림과 글꼴 배율도 계산에 포함한다.
- 항목 키를 기준으로 현재 위치를 유지한다. 앞에 항목이 추가되거나 화면 높이가 반복 변경되어도 원래 항목을 찾으며, 로딩 중 임시 빈 목록이 anchor를 지우지 않는다.
- 한 행과 버튼도 들어가지 않는 공간에서는 잘린 목록 대신 공간 안내를 표시한다. 안내 전체도 들어가지 않으면 축약 기호, 높이가 0이면 접근성 설명만 남긴다. 이 처리가 상위 화면의 모든 과도한 도구 배치를 자동으로 해결하는 것은 아니다.
- 웹 본문은 현재 DOM의 실제 크기로 분할하고 늦은 폰트 로딩 때 재측정한다. 크기 0에서는 이전 본문/페이지 정보를 비우고 원문 anchor는 보존한다. 도구 화면 진입·복귀의 임시 레이아웃은 읽기 번역에 전달하지 않는다.
- 웹 읽기 메뉴와 도구 선택기를 한 줄로 정리하고, 도구가 열리면 바깥 번역 제어 영역을 제외한다. 번역 상태 영역 높이를 고정하며 원문에서 불필요했던 56px 이동 영역을 제거했다. 높이 520px 이하의 읽기 화면은 앱 헤더·본문 도구 간격을 줄이되 44px 동작 버튼을 유지한다.
- Android 본문은 `ReaderMeasuredContent`에서 실제 글꼴·행간·여백·밀도·영역으로 표시 범위를 계산한다. 사용자 글꼴을 작게 줄이지 않고 나머지 문자를 다음 표시 페이지로 넘긴다. 원문은 인접한 텍스트 페이지를 이어 채울 수 있다. 이전/다음·터치·읽기 페이지 키가 같은 표시 위치를 사용한다.
- 번역은 현재 canonical 페이지에 제공된 실제 번역 범위를 끝까지 나눈다. 비교 화면은 더 긴 쪽의 나머지도 이동할 수 있다. 번역 대기/도착, 여백·크기 변경을 다시 측정하며, PDF는 비트맵 로딩 여부와 무관하게 물리 페이지 경계를 지킨다.
- 서버 진행 위치와 서버 북마크·메모의 열기/생성에 실제 원문 UTF-16 offset을 연결했다. 이전 페이지의 끝에서 표시 위치를 계산하는 동안 임시 offset은 업로드하지 않는다. 문단 끝의 노트는 다음 실제 텍스트 위치로 이동하며, 마지막 끝에 텍스트가 없으면 생성을 막는다.
- 웹 번역 응답이 도착해도 열린 분류 편집 화면과 초안을 유지한다. 원문 언어와 계정 기본 번역 언어가 같으면 다른 최초 대상 언어를 선택하며, 사용자가 같은 언어를 선택한 경우 요청 전에 안내한다.

## 식별자와 지원 한계

저장용 `ReaderDocument`/`ReaderPage`/segment ID, 원문 revision, 번역 캐시, ZIP 식별자를 변경하지 않는다. 화면 페이지 번호를 문서 식별자로 쓰지 않으며 Android 중앙 표시는 **문서 위치**로 구분한다. 별칭의 표시 위치는 원문 치환 범위로 역매핑한다.

번역 문자의 정확한 원문 대응 정보가 없는 경우 비율로 추정하지 않는다. 같은 번역 segment에서 알려진 원문 위치를 유지하고 원문/번역 표시 offset을 따로 관리한다. PDF 너비 맞춤 자체의 기존 표현 범위, 기존 로컬 북마크·진행 기록의 canonical 페이지 단위, Android 실제 기기의 렌더링·키 검증은 별도로 구분한다. EPUB 첫 두 이미지 제한은 **D2**, 실제 장치 검증은 **V3**에 남는다.

## 실제 브라우저 검증

미리보기 `127.0.0.1:8080`과 기존 검증 계정을 사용했다. 파괴적인 DB fixture 초기화는 실행하지 않았다.

- 390×844, 기존 원문 `읽기 위치 동기화 검증`: 본문 영역 442px, 표시 본문 약 439px. 마지막 문단의 아래 끝 717.8px가 영역 끝 721px 안에 있다. 기존 문단 10 anchor와 강조가 유지됐다.
- 1280×1000: 같은 anchor가 포함된 화면으로 재분할, 영역 561px 안에 본문 약 531px. 문서/버튼의 가로·세로 overflow 없음.
- 844×390: 기존 영역 높이 0 문제를 재현한 뒤 compact 배치로 수정. 본문 영역 106px, 본문 약 92px, 페이지 버튼 영역 340–390px로 완전히 표시된다. 전체 문서 overflow 없음.
- 분류 도구: 390×844에서 폴더·태그·즐겨찾기 세 행(각 112px)이 한 화면에 들어오며, 번역 제어 영역이 남지 않는다. 높이가 없는 목록은 잘린 행/버튼 대신 compact 접근성 상태로 전환한다.
- 실제 가져온 `browser-reading-flow` 문서에서 Google 웹 번역 실행 직후 분류 초안을 입력했다. 응답 후에도 초안이 남았고, 취소/본문 복귀 후 **준비 1/1쪽**, 실제 한국어 번역 네 문단이 표시됐다. 미저장 초안은 서버에 저장하지 않았다.
- 같은 문서에서 글꼴 36px, 행간 2.4(86.4px), 여백 48px를 적용했다. 394px 영역 안에 5쪽을 모두 표시했고, 각 문단의 다음 UTF-16 시작점이 직전 끝과 이어졌다. 모든 쪽의 마지막 문자가 영역 안에 있었으며 마지막 `cup of tea.`까지 확인했다. 검증 후 글꼴 21·행간 1.1·여백 0으로 복원했다.
- 한국어 원문에 한국어 계정 기본값이 적용되어 400이 나는 경로도 발견했다. 원문 revision 재계산은 정상 일치했다. 최종 빌드에서 최초 대상 en을 확인하고 다시 ko를 선택하면 안내가 표시되고 읽기 번역 POST가 0건임을 브라우저 네트워크 이벤트로 확인했다. 실제 Google 서비스 성공 근거는 위의 AUTO→ko 문서이다.
- 최종 모바일 스크린샷: `.gradle-home/viewport-reader-mobile.png`. 임시 브라우저 크기 override는 검증 후 해제했다.
