# 계정 비밀번호 변경

기존 계정의 비밀번호를 서버에서 바꾸고 앱·웹이 같은 계약을 사용한다. 웹은 **연결 → 비밀번호 변경**, Android는 **서버 서재 → 계정 → 비밀번호**에서 연다. 현재 비밀번호·새 비밀번호·확인을 입력한다. 화면은 한국어와 영어를 제공한다.

## 공통 계약

- `POST /api/v1/accounts/me/password`: HTTP Basic 인증과 세션 CSRF 토큰이 필요하다. [OpenAPI](../contracts/accounts-v1.openapi.json)의 `ChangePasswordRequest`는 `currentPassword`, `newPassword` 두 필드만 보낸다. 성공은 본문 없는 `204`, `Cache-Control: no-store`다.
- 비밀번호 앞뒤 공백을 유지한다. 새 비밀번호는 가입과 동일하게 10 Unicode 코드 포인트 이상, UTF-8 72바이트 이내, 제어문자 금지다. 기존 짧은 초기 비밀번호도 현재 비밀번호로 확인할 수 있다.
- 잘못된 현재 비밀번호·동일 비밀번호·새 비밀번호 규칙 위반은 `400`, 동시 변경 충돌은 `409`, 계정당 15분 5회 초과는 `429`다. 본문은 4KiB까지 허용한다. 시도 제한은 프로세스 내에서 적용한다.
- BCrypt 해시를 이전 해시와 비교하여 원자적으로 갱신한다. 계정 ID와 사용자 소유 데이터는 바뀌지 않는다. 재시작 시 초기 비밀번호 설정이 변경된 해시를 덮어쓰지 않는다.
- 인증은 요청마다 검증하고 세션에는 CSRF만 사용한다. 기존 쿠키 또는 이전 인증 세션이 변경 전 비밀번호를 계속 유효하게 만들지 않는다.

## 클라이언트 처리

성공하면 앱과 웹 모두 메모리의 기존 인증정보와 비밀번호 입력값을 지우고 새 비밀번호로 로그인하도록 안내한다. 비밀번호 입력값은 기기 보관 데이터·계정 프로필·ZIP·로그에 저장하지 않는다. 잘못된 현재 비밀번호와 요청 제한 등 확정된 오류는 고정된 번역 문구로 표시하고 서버의 임의 메시지를 노출하지 않는다.

요청 중 취소·연결 끊김·시간 초과는 서버가 이미 변경을 완료했을 수 있다. 이 경우 기존 연결을 해제하고 새 비밀번호로 로그인을 확인하도록 안내한다. 변경 요청을 자동 재시도하지 않는다. 이전 요청의 지연 응답 또는 정리 작업이 새 로그인 상태를 덮어쓰지 않도록 요청 세대·클라이언트 신원을 확인한다. Android 비밀번호 POST는 재전송이 비활성화된 OkHttp 경로를 사용한다.

## 2026-09-16 검증

- 웹 계약 6개 생성 일치·타입 검사·프로덕션 빌드·217개 테스트 통과. UTF-8/공백·확인 입력·CSRF·204·오류 코드·응답 크기 제한·늦은 응답·시간 초과 검사를 포함한다.
- 격리 PostgreSQL에서 서버 전체 87개 통과. 기존 인증 쿠키, 이전 비밀번호 거부, 새 비밀번호 로그인, 원문·프로필 유지, 초기 계정 변경, 동시 요청 충돌을 검증했다.
- Android 287개 통과, 기존 선택 검사 15개 제외, debug APK 빌드 성공. 신규 12개에 실제 loopback HTTP CSRF→204, 응답 유실 시 POST 재전송 방지, 취소 후 새 로그인 보존을 포함한다. 실제 기기 화면 계측은 실행하지 않았다.
- 실행 중인 8080 서버의 별도 검증 계정으로 실제 HTTP 요청을 실행했다. 잘못된 현재 비밀번호 `400`, 정상 변경 `204`, 이전 비밀번호 `401`, 새 비밀번호 로그인·계정 ID·언어 설정·저장 원문 유지 모두 확인했다. 일반 미리보기 계정의 비밀번호는 변경하지 않았다.
- 웹 390×844에서 계정 설정 → 비밀번호 변경 진입·3개 입력란·복귀·제출 버튼을 확인했다. 문서 크기는 390×844, 입력란/버튼은 모두 44px 이상이다. 브라우저에서 비밀번호 변경 제출까지 자동 실행한 검증은 아니다.

이메일 인증, 비밀번호를 잊었을 때의 재설정, OAuth는 아직 구현하지 않았다. 현재 비밀번호를 아는 사용자의 변경 흐름만 포함한다.
